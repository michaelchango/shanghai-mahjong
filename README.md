# 一道来麻将（上海敲麻 · 敲麻 / 清混碰）

上海敲麻规则的麻将游戏，一个**单文件 HTML** 玩法本体 + 轻量 Node 联机服务端，手机上用浏览器直接打开就能玩。

- **玩法可选**：设置里切「敲麻 / 清混碰」——敲麻有平胡兜底（垃圾胡 0 番）、中发白算花；清混碰只认碰碰胡 / 混一色 / 清一色 / 风一色，中发白算牌不算花
- **单机模式**：1 个真人 + 3 个机器人，零网络依赖，断网/飞行模式照样玩
- **多人模式**：好友开房间，4 人联网对战，界面与单机一致，规则由服务端权威判定

## 运行

### 单机

把 `index.html` 传到手机（微信/邮件/网盘均可），用浏览器打开即可。

1. 首页点 **单机游戏** → 先弹规则设置面板，底部「**返回** / **开始游戏**」——可直接调好玩法再开局
2. 局内右上角 ⚙ 改设置：点「完成」会提示**会清空本局记录并重新开局**（确定才重开）
3. iOS：Safari 打开 → 可「添加到主屏幕」；Android：Chrome 打开 → 可「添加到主屏幕」

> 更新版本后如果界面没变化，多半是浏览器缓存了旧文件，清一下缓存即可。

### 多人（好友开房间）

需要一台运行服务端的机器（电脑/云服务器均可，1 核 1G 就够）：

```bash
cd server
npm install          # 只装一个 WebSocket 依赖
node server.js       # 默认 8080 端口；换端口： PORT=9000 node server.js
```

服务端启动后，所有玩家用手机浏览器访问 `http://<服务器IP>:8080`：

1. 首页 → **多人对战**
2. 填昵称；服务器地址**留空即可**（自动用当前页面地址）
3. **创建房间** → 得到 6 位房间号；或输入好友的房间号 **加入**
4. 等待页是一张**简易牌桌**：中央一个显示东南西北的迷你罗盘圆，四个边是四个位子。进房自动落座；**点空位可以换过去**（有人坐的位子点不了），换座后所有人立刻看到新座位图。加入的人点「准备」（**房主不需要准备**）→ 全员就绪后房主点「开始游戏」
5. 人没坐满就开局的话，空位自动补机器人（空位不看准备状态）
6. 一局结束后：每人点「准备下一局」（自己牌河显示「准备」字样，可取消），**四家都准备后自动进入下一局**（机器人/掉线者自动算已准备）

**部署到公网**（好友各在各家时）：把服务端跑在一台有公网 IP 的机器上（云服务器、云托管等），开放对应端口即可。规则计算全部在服务端完成，客户端只负责显示，流量开销很小（每步约 1.6 KB）。页面走 HTTPS 时，客户端会自动改用加密的 `wss://` 连接，无需额外配置。

### 房主能做什么

| 操作 | 在哪 | 效果 |
|---|---|---|
| 开始游戏 | 房间等待页 | 所有已加入的真人都准备后开局；有人未准备时按钮**置灰**（不消失），空位自动补机器人 |
| **游戏设置** | 房间等待页 | 打开和单机右上角同一套规则（玩法敲麻/清混碰 · 底 / 每花分值 / 勒子 / 自动敲 / 自动胡 / 速度 / 吃牌 / 七小对）。房主点「确定」提交后广播给全房间；非房主只读（顶部提示「规则由房主设定，开局后锁定」）。**开局后锁定**，所有人都只能看 |
| **移出玩家** | 房间等待页 · 其他玩家座位上 | 把某人请出房间（解决掉线堵住开局）。牌局中不可用，需先「结束本局」 |
| 结束本局 | 牌局中 · ⚙ 设置面板 | 中止当前牌局，所有人回到房间等待页，房间号不变（准备状态会重置） |
| 关闭房间 | ⚙ 设置面板 / 房间等待页 | 房间解散，所有人踢回首页，房间号立即失效 |

等待页说明：

- 座位图按**自己的视角**排布：自己永远在下方，右家/对家/左家与进牌局后的方位一致；中央圆的方位字也跟着视角走
- 房主身份**跟着人走**：房主换座仍是房主；房主退出/被移出后才顺延给首个在座者
- 底部实时显示「X 位真人入座，还有 Y 位未准备」，任何人（取消）准备，四家看到的数字同步刷新

非房主设置面板只读（渲染成文本，没有按钮，底部仅「关闭」）。移出和关闭房间都有二次确认。

### 中途退出与重进

- 牌局中退出：座位由机器人托管，牌局继续；**只要牌局还在，随时能顶替回来**
- 想回到正在打的这一局：用**相同昵称 + 同一房间号**加入，直接顶替回原座位继续打
- 所有人都退出：牌局进行中时服务端 1.5 秒后自动中止牌局、释放座位，房间号仍然有效，随时能重新进入；**一局已结算（等准备下一局）时不会中止**，结算数据保留，重连回来仍能查看
- 重连回到已结算的结束状态：服务端会补发本局结算数据，底部「查看结算」按钮正常弹出结算面板
- 首位重新进入的人自动成为房主
- 等待中掉线：座位**保留 5 分钟**，宽限期内同昵称可以直接坐回原位
- 等待中最后一人掉线：房间**当场销毁**

### 断线自动重连

浏览器切后台、网络切换、息屏一段时间都可能让连接悄悄断掉。客户端的处理：

| 触发 | 行为 |
|---|---|
| 连接断开 | 退避重连（1.8 秒起、最长 6 秒，最多 8 次），界面提示「正在重连(N)」 |
| 切回前台 | 立即发 ping 探活；3 秒内无回应判定为半开连接，强制断开重连 |
| 重连被拒（房间已解散 / 凭证无效） | 停止重试，回首页并说明原因 |
| 断线时点「结束本局 / 关闭房间」 | 提示「连接已断开，正在重连…」并立即重连 |

重连成功后自动补发牌面与当前待办操作，接着打即可。

### 房间回收

房间只存在在服务端内存里，进程重启即全部清空。此外**每 1 小时扫一次**，一次扫描把所有满足条件的房间一起处理：

| 情形 | 阈值 |
|---|---|
| 等待中的房间，无人操作 | **2 小时** |
| 牌局挂起无进展 | **2 小时** |
| 无人留守 | **2 小时** |

牌局正常推进时会不断刷新活动时间，正常玩牌不会被误回收。三种情形共用同一个阈值（统一为 2 小时），牌局挂起时先中止牌局、再释放房间。

阈值可用环境变量覆盖，方便验证：

```bash
SCAN_INTERVAL=1000 ROOM_IDLE_TIMEOUT=3000 OFFLINE_GRACE=2000 node server/server.js
```

## 规则

### 两种玩法（设置 · 玩法）

| | 敲麻 | 清混碰 |
|---|---|---|
| 可胡牌型 | 平胡（垃圾胡 0 番）兜底 + 下列番型 | 只认 **碰碰胡 / 混一色 / 清一色 / 风一色**（及其复合） |
| **敲听** | **必须先敲定才能胡**（不敲不能胡，敲后锁听） | **免敲**——没有敲定步骤，能胡的牌点炮/自摸直接胡（顶部实时显示听牌） |
| 中发白 | **算花**（12 张当花牌，摸到即补） | **算牌不算花**（可碰、可组刻/将，作字牌参与混一色 / 风一色） |
| 副露定方向 | 不锁（平胡允许顺子刻子混打） | **碰过即不吃**——碰/杠过任何数牌后吃按钮彻底消失（清混碰靠碰做一色/碰碰胡）；没碰过时可吃，吃过即锁该门（只能本门+字），**其他花色的吃碰杠不再提示** |
| 机器人 | 平胡为主，能吃则吃 | 边打边判断（实时切换碰碰胡/混/清/风目标，且**目标不与已有副露冲突**），不吃不符合自己目标花色的牌 |

> 清混碰四种番型：**碰碰胡**（4 刻+将）、**混一色**（一门数牌 + 字牌[风/中发白]）、**清一色**（纯一门数牌）、**风一色**（全字牌）。风一色含中发白，全字七对也算。

### 敲麻核心

| 规则 | 说明 |
|---|---|
| **不敲不能胡** | 必须先报听（敲）才有资格胡牌 |
| **敲后锁定** | 不能换牌、不能吃碰，摸什么打什么 |
| **胡牌按钮** | 默认满足胡牌条件时显示「胡」按钮，**点了才胡**（自摸/点炮统一），点「过」则弃胡继续；设置里开「**自动胡牌**」则能胡就自动胡（含敲定后的点炮） |
| **有杠必杠** | 敲定后摸到可杠的牌自动杠；**未敲定**时摸到能杠的牌显示「暗杠 / 加杠」按钮 |
| **漏胡** | 放弃胡某张牌后，动牌之前不能再胡同一张 |
| **吃碰杠优先级** | 分轮询问：**胡 > 杠=碰 > 吃**（先问胡，没人胡问杠碰，没人碰问下家吃） |
| **听牌多选** | 敲听时打不同的牌会听不同的牌，弹出面板选打哪张 |

### 牌型与番数

| 牌型 | 番 | 牌型 | 番 |
|---|---|---|---|
| 碰碰胡 | 2 | 清一色 | 4 |
| 混一色 | 2 | 清碰 | 5 |
| 混碰 | 3 | 风一色 | 5 |
| 七小对（敲麻可选） | 3 | 风碰 | 9 |
| 垃圾胡 / 平胡（仅敲麻） | 0 | | |

> 复合番 = 一色 + 碰碰胡叠加（如清碰 = 清一色 + 碰碰胡）。清混碰下风一色含中发白，全字七对也算风一色。

**附加番**：门清 +1、无花果 +1、大吊车 +1、杠上开花 +1、海底捞月 +1、地胡 +8、天胡 +8

### 底（花）与算分

- **底 = 起底 + 花数**。花牌来源：季/花牌每张 1 花、**敲麻玩法中发白每张算 1 花**（清混碰中发白是牌不算花）、数牌明杠/暗杠 1/2、风牌刻子/明杠/暗杠 1/2/3
- **得分 = 底 × 番 × 每花分值**（线性番，v1.2.23：N 番 = 底×N；0 番兜底 ×1），单份封顶 N 勒（1 勒 = 10 花）
- **自摸**：三家各付一份；**点炮**：点炮者付一份（一炮多响各付一份）
- **开宝**：骰子为豹子或 1·4 点，本局得分与封顶 ×2
- **荒番**：上一局流局，得分与封顶 ×2^荒番数，有人胡后荒番 −1

## 界面说明

| 区域 | 内容 |
|---|---|
| 四家面前（各自视角，由近到远） | 手牌区 → 花+吃碰杠区 → 牌河区 |
| 名牌 | 名字 + `N分`（底×番明细已移入结算面板） |
| 听牌标记 | 敲定后手牌/牌背上出现「听」圆章 |
| 吃碰来源 | 牌组中间那张牌上的箭头，指向打出这张牌的那一家 |
| 桌心圆 | 东南西北四风位 + **圆心纯数字倒计时**（黄色高亮，≤3 秒转红闪烁；无人决策时留空）——有人在做决策时四家**同时**看到同一个数（超时由系统自动代打） |
| 圆**上方** | 骰子点数 + 剩余牌数一行（放不下骰子缩小；豹子/开宝只高亮骰子） |
| 圆**下方** | 最近出牌记录，**最多三手**、空间不够自动减为 2/1/0 行（绝不重叠）+ 「全部手牌记录」 |
| 东南西北 | 方位块贴在圆边上，当前出牌者的指针**直接穿过圆的边框向外戳出**（遮住一点圆边），带呼吸动画 |
| 点手牌算张 | 选中一张手牌时，四家牌河 + **自己吃碰杠区**里同牌全部高亮（亮蓝 3px 框 + 光晕），方便算台面剩几张 |
| 底部边框下方 | 敲定后显示「听牌中 → xx 牌」（未敲时自动收起）；**只差一张牌**（唯一听法）时按钮上方还会提示「听牌中 → xx · 还有 n 张」 |
| 结算后底部 | 单机「查看结算 / 下一局」；多人「回到首页 / 查看结算 / 准备下一局」 |
| 右上角「记」 | 本轮所有已结算牌局的历史记录，可回看任意一局 |
| 吃 / 碰 / 杠 / 敲 | 在**当事人自己的牌河区域正中**弹金底浮窗，**停留 2 秒**后消失 |
| 听牌提示 | 敲听提示与「选择听法」面板里，每张听牌标注**台面剩余张数**，如「听 九萬(2)」（4 − 自己手牌 − 三家牌河 − 吃碰杠，不算其他三家手牌） |
| 操作按钮 | 自动均分宽度，按钮少则宽、多则窄，文案过长时缩小字号，**永不换行** |
| 多人局间「准备」 | 谁点了「准备下一局」，**四家都能**在其牌河区看到「准备」字样（可取消） |

## 设置

右上角 ⚙ 可调整：

| 设置 | 说明 |
|---|---|
| **玩法** | 敲麻 / 清混碰（见「规则 · 两种玩法」） |
| 底（底花）/ 每花分值 / 封顶勒子 | 算分规则 |
| **自动敲牌** | 开 = 能听牌自动敲定（联机机器人也会自动敲） |
| **自动胡牌** | 开 = 能胡就自动胡（含敲定后点炮）；关 = 每次都出「胡 / 过」按钮 |
| 允许吃牌 / 七小对 | 可选开关 |
| 机器人速度 | 出牌节奏 |

- 单机设置保存在手机本地（`localStorage`），不联网、不上传
- **单机**：首页「单机游戏」先弹设置（返回 / 开始游戏）；牌局中改设置点「完成」会**清空本局记录并重新开局**（有确认弹窗）
- 多人对战时：
  - **等待页**：房主可改（点「确定」才提交，提交后其他人顶部弹「房主修改了游戏设置」）；其他人**可查看**（只读，没有按钮，底部仅「关闭」）
  - **牌局中**：所有人**只能看不能改**（包括房主）
  - 退出联机后自动恢复本机自己的单机规则

历史记录按「轮」累计，**只有开始新一轮（或重开一桌）才会清零**。

### 核心原则：规则只有一份

服务端不另写一套规则，而是由脚本从 `index.html` 抽取：

```bash
node proto/tools/extract.js            # 抽取引擎（含服务端适配补丁）→ 显式检查退出码为 0
node proto/server/simulate.js 200      # 200 局无头仿真 + 可见性裁剪验证
node tests/unit.js                     # 引擎单元测试 62 项
node tests/m37_qhp_game.js             # 清混碰 AI 24 局对局回归（花色锁/达成率）
```

抽取时对引擎施加的补丁是机械、可审查、向后兼容的（座位参数、服务端钩子、漏胡服务端化等），保证「单机一套规则、联机一套规则」的漂移永远不会发生。

### 联机架构：服务器权威

```
手机 ×4                       服务端
─────────                     ───────
渲染投影   ←── view ────────  规则引擎（同一份代码）

```
